# 01 — What the three consumers have that the boilerplate does not

Inventory only. The decision of what to take, and at which tier, is [03](./03-backport-plan.md).

Three repos descend from this boilerplate:

| Repo          | Host                                           | API toolchain                         | Workflow system                             |
| ------------- | ---------------------------------------------- | ------------------------------------- | ------------------------------------------- |
| **batch**     | Cloudflare Workers + D1 + R2                   | oxlint 1.83 + oxfmt 0.68, lint-staged | chisel — `.agents/` + `project-management/` |
| **treashunt** | Cloudflare Workers + D1 + R2 + Durable Objects | oxlint 1.85 + oxfmt 0.70, lint-staged | Spec Kit — `.specify/` + `specs/`           |
| **keeper**    | Docker + Postgres + S3                         | `vp` (vite-plus 0.2.8), knip          | openspec — `.agents/skills/openspec-*`      |
| _boilerplate_ | _Cloudflare Workers + D1 + R2_                 | _`vp` 0.2.8, knip, husky_             | _none — `docs/specs/` is hand-written_      |

The split is clean: **batch/treashunt share a toolchain, keeper shares ours.** Where they
disagree, keeper is the better guide for this repo.

consumer inherited and then improved. These are the highest-value backports because they are
generic by construction.
